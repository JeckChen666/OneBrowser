# V0.2.0 版本执行计划

> 日期：2026-10-10。前置：V0.1.0（M0–M4）已完成并通过 16 项 e2e。
> 版本主题：**指纹环境版（M5）** —— 让每个环境成为一台跨设备一致的「独立设备」；并行启动 **M6 预研**；补齐 V0.1 遗留小项。

---

## 0. 依赖事实（已验证，2026-10-10）

[fingerprint-chromium](https://github.com/adryfish/fingerprint-chromium)（BSD-3）预编译产物覆盖：

| 平台 | 覆盖情况 |
|---|---|
| Windows x64 | ✅ 每版都有（installer + portable zip） |
| Linux x86_64 | ✅ 每版都有（AppImage + tar.xz） |
| macOS Intel | ⚠️ 仅 148.0.7778.215 有 DMG；150 已不再发 macOS |
| macOS ARM64 / Win ARM64 | ❌ 无 |

结论：内核获取必须做成**可插拔**（官方预编译 / 用户自备本地路径 / 未来自建 CI）；本开发机（darwin x64）用 148 Intel DMG 验证；mac ARM64 列为已知缺口。

关键能力（来自调研 §3.3，已实读补丁）：`--fingerprint=<seed>` 种子驱动整套指纹（UA/Canvas/WebGL/Audio/字体/ClientRects/核数/内存…），`--fingerprint-platform`、`--timezone`、`--accept-lang`、`--proxy-server`。**同 seed 跨设备指纹一致**正是本版本的核心验收点。

## 1. 版本范围

### A. 内核管理模块（`src/main/core/kernelManager.ts`）

- 内核仓库抽象：`KernelSource` 接口，默认实现 `GitHubReleaseSource`（查 Releases → 按 OS/arch 选产物 → 下载 → sha256 校验 → 解压到 `userData/kernels/<version>/`）
- 支持用户自备：设置页指定本地内核可执行文件路径（绕过下载，覆盖 mac ARM64 场景）
- 版本管理：多版本并存（目录 per version），环境级 `kernelVersion` 可指定，缺省用最新；损坏可删重下
- 首次使用引导：创建「指纹承载」环境时自动触发下载（200MB+，进度条 + 断点续传）
- 安全：产物 sha256 落库校验；执行前校验路径在 kernels 目录内

### B. 外挂内核承载（`ExternalKernelHost`）

- 与现有 `BrowserHost`（Electron partition）实现同一接口，新增实现：
  - spawn 内核进程：`<kernel> --user-data-dir=<userData>/kernels-profiles/<envId>-<runToken> --fingerprint=<seed> [--fingerprint-platform=..] [--timezone=..] [--lang=..] [--proxy-server=..] --remote-debugging-port=<动态端口>`
  - **数据目录仍为一次性**（runToken 后缀，关闭即删）：保持「分支」语义与 V0.1 一致
  - CDP attach（`ws://127.0.0.1:<port>/devtools/browser`）用于数据面与生命周期控制
  - 生命周期：进程退出 → 触发 onClosed；驱逐时先 capture 再 kill
- 环境新增属性 `hosting: 'builtin' | 'kernel'`（存于 config_enc）：
  - `builtin` = V0.1 的 Electron partition 轻量模式（保留，无指纹、秒开）
  - `kernel` = 指纹模式（默认值，产品主打）
  - V0.1 已建环境不迁移，保持 builtin
- **UX 附带升级**：kernel 模式的环境窗口就是内核原生浏览器窗口（自带地址栏 + 多标签），解决 V0.1 环境窗口无地址栏的问题

### C. CDP 数据面（`dataPlaneCdp.ts`）

- 用 CDP 实现与 `dataPlane.ts` 相同的 capture/restore 接口：
  - cookie：`Storage.getCookies` / `Network.setCookies`（等价 session.cookies，字段映射）
  - localStorage：`Page.navigate` 到 origin 后 `Runtime.evaluate` 读写（复用现有注入脚本）
- origin 清单：通过 CDP `Page.frameNavigated` 事件跟踪
- **快照格式不变**（blob 仍是结构化 JSON）→ builtin 与 kernel 两种承载**共享同一份云端基线**，可互迁移（验收 T12）

### D. 指纹配置模型（简化版 25-surface）

- `EnvConfig.fingerprint`：`{ seed, platform?, timezoneMode: 'seed'|'auto'|'manual', timezone?, langMode: 'seed'|'auto'|'manual', lang? }`
  - `auto` = 按代理出口 IP geo 查询自动设置（服务端加一个 `GET /v1/geo?ip=` 薄接口，用离线 IP 库；无代理时用本机出口 IP）
  - V0.2 不做完整 25-surface UI；高级覆盖后续版本再加（字典先以 seed 内置为准）
- 指纹字典（时区↔国家、语言↔地区映射表）：自带精简 JSON（数据来源公共时区表），不依赖 VirtualBrowser 的 AGPL 相邻资产

### E. V0.1 补强（小项，随版本带走）

- **快照保留策略**：服务端 commit 时保留每环境最近 N=5 份 ready 快照，超额删除（DB 行 + S3 对象）；可配置
- 上传失败重试：`putObject` 网络错误重试 3 次（指数退避）
- e2e 断言补齐：把 V0.1 手工项 T6（会话过期→提示重新登录）自动化

### F. M6 预研（并行线，不阻塞主线，产出 V0.3 Go/No-Go）

1. fingerprint-chromium 源码构建跑通（macOS x64 本机或 Linux 容器，产出一次完整构建文档与耗时记录）
2. **os_crypt 可漫游补丁 PoC**：打补丁让 cookie 加密用应用层密钥 → 双机拷贝 `Network/Cookies` 文件验证可解（调研报告 Phase 0 的核心实验）
3. 产出物：`docs/m6-research.md`（构建流程、补丁草案、实验结果、工作量评估）

### 不做（Non-goals，推迟到 V0.3+）

IndexedDB/Service Worker 文件级快照（M6 正式）、自研内核补丁的正式集成与多版本维护、25-surface 完整配置 UI、团队协作/多用户、安装包分发与自动更新、浏览器扩展管理、移动端

## 2. 架构变更

```
BrowserHost（接口，V0.1 已有）
 ├─ BuiltinHost        Electron 内存 partition（轻量模式，现状保留）
 └─ ExternalKernelHost 指纹模式（新）
      ├─ kernelManager     下载/版本/校验/路径
      ├─ spawn + flags     seed/platform/timezone/lang/proxy
      └─ CDP 连接 ──────────► dataPlaneCdp（capture/restore，同接口同快照格式）
                                │
AppService（不变） ─────────────┤ 快照引擎/云端/租约全部复用
服务端变更：+ /v1/geo、快照保留清理（commit 内）；无 schema 破坏性变更
```

数据模型变更（均在 config_enc 内部，服务端 schema 不动）：`EnvConfig` + `hosting` + `fingerprint` + `kernelVersion?`。

## 3. 验收矩阵（新增 T9–T15，自动化进 `pnpm e2e`）

| # | 场景 | 断言 |
|---|---|---|
| T9 | kernel 模式打开环境 → 访问 /fp | UA/canvas hash/WebGL vendor/时区 ≠ 宿主机真实值（指纹生效） |
| T10 | **同 seed 跨设备一致**（双实例模拟） | 两台「设备」/fp 全项一致（产品核心承诺） |
| T11 | 不同 seed 的两个环境 | canvas hash / UA 等不同（环境间隔离） |
| T12 | **双承载互迁移** | builtin 保存的基线 → kernel 模式打开登录态有效；反向亦然 |
| T13 | 代理链路 + IP 风控 | bind-ip 开启 + 环境走本地 socks5 代理 → 通过；timezoneMode=auto 时 /fp 时区与代理出口匹配 |
| T14 | 保留策略 | 上传第 6 份快照后最旧 ready 快照（DB+S3）被清理 |
| T15 | 内核管理 | 首次自动下载并校验；损坏目录检测与重下 |
| T6R | 会话过期（自动化补齐） | /api/expire 后打开环境 → UI 呈现「基线失效，请重新登录并更新基线」 |

回归：V0.1 的 T1–T3、T5 全部保持通过（builtin 模式回归 + kernel 模式各跑一遍核心链路）。

## 5. 风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| fingerprint-chromium 停发 macOS / 本机 148 版 flags 支持差异 | 中 | 内核源可插拔（自备路径）；S1 第一个任务即在 mac x64 + 148 上实测全部 flags |
| GitHub Releases 下载可达性/慢（国内环境） | 中 | 支持镜像前缀（ghproxy 类）与用户手动放置；下载器带断点续传 |
| 内核 200MB+ 首次下载体验 | 中 | 进度 UI + 仅按需下载（创建 kernel 环境才触发） |
| CDP 动态端口被本机其他进程访问 | 中 | 绑定 127.0.0.1 + 随机端口 + 进程退出即关；后续加 token 校验 |
| ungoogled 内核缺 Google API/Widevine（部分站点异常） | 低 | 记录为指纹模式已知差异；测试站不受影响 |
| spawn 多内核进程的内存占用（多环境并行） | 低 | 环境数提示 + 内核复用调研（V0.3） |
| 保留策略误删（based_on 链被清理） | 低 | 只清理非 latest_base 的最旧 ready；删除前校验引用 |
